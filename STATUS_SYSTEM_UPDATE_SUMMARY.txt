OVERVIEW:
---------
Implemented a comprehensive status workflow system for quotation records with 
sequential action states, confirmation prompts, and dynamic UI controls.

CORE FEATURES IMPLEMENTED:
--------------------------

1. STATUS WORKFLOW (Sequential: 1→2→3→4)
   =====================================
   
   Status 1: "quotation complete" or "quotation complete (#2)", "#3", etc.
   - Initial creation: "quotation complete"
   - After edits: "quotation complete (#revision_number)"
   - Available Actions: View (edit) + Submitted to Customer
   
   Status 2: "quotation send to customer"
   - Available Actions: View (read-only) + Price Approved
   - Edit functionality disabled
   
   Status 3: "price approved"
   - Available Actions: View (read-only) + Start Sampling
   
   Status 4: "sampling"
   - Available Actions: View (read-only) only
   - All other actions disabled

2. CONFIRMATION PROMPTS
   ====================
   - "Submitted to Customer": "Are you sure you want to mark this quotation as submitted to customer?"
   - "Price Approved": "Are you sure you want to approve the price for this quotation?"
   - "Start Sampling": "Are you sure you want to start sampling for this quotation?"

3. DYNAMIC UI CONTROLS
   ===================
   - Buttons automatically enable/disable based on current status
   - Disabled buttons appear dimmed (opacity: 0.4, color: #999)
   - Active buttons have normal styling
   - View button text changes: "View (edit)" → "View" when editing disabled

API ENDPOINTS:
==============

New Endpoint: PUT /quotation/status/<quotation_id>
- Purpose: Update quotation status for workflow actions
- Payload: {"action": "submitted-to-customer|price-approved|start-sampling"}
- Response: {"message": "Status updated successfully", "status": "new_status"}
